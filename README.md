# МаниЛи EVENT — сайт + админка

Готовый production starter: публичный сайт + `/admin/` + Supabase Auth/Postgres/Storage.

## Новое: переключатель Dark/Light темы + кнопки в углу фото
- **Кнопки «Скачать» и «Поделиться»** в полноэкранном просмотре фото/видео теперь в правом нижнем углу (было — левый верхний).
- **Переключатель темы** — в шапке всех трёх страниц сайта (главная, событие, альбом): горизонтальный переключатель с бегунком, подпись «Theme: Light» / «Theme: Dark», без иконок/градиентов — строго по присланному ТЗ. По умолчанию — тёмная тема. Выбор сохраняется (localStorage) и одинаков на всех страницах, переживает обновление страницы и переходы между разделами.
- Полноэкранный просмотр фото/видео (лайтбокс) я специально оставил всегда тёмным независимо от выбранной темы сайта — это обычная практика для просмотрщиков медиа (как в Instagram/Google Photos), чтобы сами фото и видео смотрелись контрастно в любом режиме.
- **Админ-панель (/admin/) переключатель не получила** — это рабочий инструмент управления сайтом, а не публичная страница, и там уже есть отдельная настройка «фон сайта» для бренда. Если всё же нужно и в админке — скажи, добавлю отдельно.
- Референс-картинку из ТЗ ты не приложил, я реализовал строго по подробному текстовому описанию (форма, положение бегунка, цвета, текст). Если что-то не совпадёт с референсом визуально — пришли картинку, поправлю один в один.
- Новый файл на хостинг: `theme.js`. SQL запускать не нужно.

## Новое: страница альбома, превью в админке, скачать и поделиться
- **Починено превью в админке**: в разделе «Альбомы» и «Афиши» видео и фото теперь всегда показывают миниатюру (раньше видео отображалось пустым прямоугольником — не было стиля под `<video>`, теперь есть).
- **Открытие альбома**: клик по обложке альбома на сайте теперь ведёт на отдельную страницу `album.html?id=...` со всеми фото и видео этого альбома сеткой — не нужно листать стрелочкой, чтобы увидеть всё. А клик по конкретному фото/видео внутри этой сетки по-прежнему открывает полноэкранный просмотр со стрелками «вперёд/назад».
- **Скачать и поделиться**: в полноэкранном просмотре (на странице альбома и на странице события) теперь есть две кнопки — скачать текущее фото/видео к себе на устройство и поделиться (на телефоне откроется системное меню «Поделиться», на компьютере — быстрые ссылки на Telegram/WhatsApp/ВКонтакте и «скопировать ссылку»).
- На хостинг нужно добавить два новых файла: `album.html` и `album.js`. SQL запускать не нужно — правки только в файлах сайта.

## Исправление (важное, надёжное): раздел «Альбомы»
Прошлая правка угадывала точное системное имя связи между таблицами — это оказалось ненадёжно. В этой версии я убрал угадывание вообще: фото/видео альбома теперь загружаются отдельным запросом и склеиваются в коде. Это гарантированно работает независимо от того, как называется связь внутри базы. **SQL запускать не нужно** — только перезалить файлы.

## Исправление: «Раздел «Альбомы» пока недоступен» / ошибка embed (предыдущая попытка)
Точная причина найдена: между таблицами `albums` и `album_media` есть связь в обе стороны (`album_media.album_id → albums` и `albums.cover_media_id → album_media`), и Supabase не мог сам понять, какую из них использовать. Это правится **только в коде сайта, SQL запускать не нужно** — в этой версии связь указана явно. Просто перезалей файлы `app.js`, `event.js`, `admin/app.js` (или весь архив) на хостинг — и раздел заработает без повторного выполнения миграции.

## Исправление: раздел «Альбомы» не работал (первая причина, тоже уже исправлена)
Если кнопки в разделе «Альбомы» не реагировали — причина в самой базе данных: при повторном запуске старого `migration_all.sql` один шаг (добавление связи «обложка альбома») мог завершиться ошибкой и прервать выполнение файла до конца, из-за чего часть прав доступа для альбомов не была создана. В этой версии `migration_all.sql` это исправлено — шаг стал безопасным для повторного запуска. **Нужно заново выполнить обновлённый `migration_all.sql` целиком** — это ничего не удалит и не сломает, только доставит недостающие права. После этого раздел «Альбомы» полностью рабочий: создание альбома, название/описание/привязка к событию, публикация, загрузка нескольких фото и видео сразу, выбор обложки, порядок, удаление отдельных файлов и всего альбома.

## Что нового: платформа продажи билетов (эта версия)
- у события теперь есть точные дата/время (для обратного отсчёта), город, статус билетов, слаг для собственной страницы и промо-видео;
- **страница события** `event.html?slug=...` — hero/промо, дата/время/город/зал, описание, категории билетов с ценами и статусами, обратный отсчёт, медиа-альбом этого события;
- **категории билетов** (обычный/VIP и т.д.) — своя цена, статус (Скоро / В продаже / Почти распроданы / Распроданы / Продажи закрыты) и своя ссылка на покупку у каждой; управляются прямо в карточке события в админке;
- **промо-блок на главной** — крупное видео/фото ближайшего события с обратным отсчётом и кнопкой покупки; появляется автоматически, когда у события включено «показывать промо на главной»;
- **альбомы** вместо плоской галереи — фото и видео внутри одного альбома, обложка (фото или видео), счётчик «N фото · M видео», публикация/черновик, привязка к событию; открываются в полноэкранной галерее (лайтбоксе) со стрелками;
- прошедшие события (статус «Архив») сохраняют свою страницу с описанием и медиа — это архив, история МаниЛи.

**Важно про ограничения**: реального приёма оплаты и учёта проданных мест в проекте нет — «Купить билет» ведёт на внешнюю ссылку (как и раньше), а статус билетов переключается вручную в админке, а не автоматически по остатку мест. Это осознанное решение: подключение реального платёжного провайдера — отдельная задача, которую нужно обсуждать отдельно (нужен онлайн-эквайринг/провайдер, юрлицо, обработка возвратов и т.д.).

### Что нужно сделать один раз
1. Supabase → SQL Editor → выполнить `migration_all.sql` целиком (файл уже включает всё — категории билетов, альбомы, промо, старые обновления).
2. Залить все файлы этого архива на хостинг, включая новые `event.html` и `event.js`.
3. В `/admin/` у каждого события заполнить точные дату/время (если нужен обратный отсчёт), статус билетов, категории билетов; создать альбомы в разделе «Альбомы»; включить промо для ближайшего события.

Бренд «МаниЛи» и базовая цветовая палитра не менялись.

## Что умеет
- публичная главная страница `index.html`;
- события из базы появляются на сайте после статуса «Опубликовано» (прошедшие — «Архив»);
- `/admin/` — вход по email/паролю;
- создание, редактирование, удаление событий;
- загрузка и замена афиш прямо из админки;
- полностью редактируемый текст, соцсети, логотип, фон и формат афиш;
- адаптивная мобильная версия;
- RLS-права: только пользователи из `admin_users` могут менять данные.

Supabase Auth + RLS используются для аутентификации и авторизации; publishable/anon key допустим в браузере, секретный/service-role key сюда добавлять нельзя. См. официальную документацию Supabase.

## Быстрый запуск (новый проект с нуля)
1. Создай проект на Supabase.
2. Открой SQL Editor и выполни `supabase-schema.sql` целиком.
3. Затем выполни `migration_all.sql` целиком — он добавит весь остальной функционал (контент, соцсети, галерею, логотип, фон, формат афиш).
4. В Authentication → Users создай пользователя администратора.
5. Скопируй UUID пользователя и выполни:
   `insert into public.admin_users(user_id) values ('UUID_ПОЛЬЗОВАТЕЛЯ');`
6. Открой Project Settings → API и возьми Project URL + Publishable key (или legacy anon key).
7. В `config.js` вставь эти два значения.
8. Залей содержимое этой папки на хостинг сайта так, чтобы `index.html` был корнем, а папка `admin` была доступна как `/admin/`.
9. Открой `https://manili.ru/admin/`, войди и создай событие со статусом «Опубликовано».

## Если сайт уже был развёрнут раньше (обновление)
1. Supabase → SQL Editor → выполни `migration_all.sql` целиком (ничего не удаляет, только добавляет — повторный запуск безопасен).
2. Залей файлы этого архива поверх текущих на хостинге.
3. Зайди в `/admin/` → «Контент сайта», «Соцсети», «Галерея» — заполни всё, что нужно.

## Важно про безопасность
Не вставляй `service_role` или Secret key в `config.js`. Браузер должен использовать только publishable/anon key. Доступ к изменению событий и загрузке файлов ограничен RLS и `admin_users`.

## Если используешь обычный хостинг
Этот проект — статический frontend, поэтому подходит Beget, Timeweb, обычный VPS/Nginx, Vercel, Netlify и т.п. Для обычного хостинга достаточно загрузить файлы через FTP/файловый менеджер.

## Домен
Если `manili.ru` уже подключен к хостингу, не меняй DNS без необходимости. Просто загрузи файлы в document root. Если сайт сейчас существует, сначала сделай резервную копию.

# МаниЛи EVENT — отчёт по аудиту и правкам (v1)

Статический анализ + правки кода. Дизайн/анимации/лого не менялись — п.25 ТЗ
трактован как общие guardrails («не неон, не клубный шаблон»), а не задача на
редизайн (см. README: «бренд и палитра не менялись»).

## Что реально исправлено

**Безопасность (реальная находка).** `ticket_categories` была публично читаема
через `using (true)` — то есть цены и ссылки на билеты ЧЕРНОВЫХ событий можно
было получить напрямую через публичный API, даже не видя само событие.
→ `migration_security_fix.sql`: теперь категория билетов видна, только если её
событие опубликовано/в архиве. **Нужно выполнить в Supabase → SQL Editor.**

**Устойчивость / нет белого экрана.** `app.js`, `event.js`, `album.js`,
`admin/app.js` — все обращения к Supabase обёрнуты в try/catch с понятными
русскими сообщениями («не удалось загрузить», «проверьте интернет») вместо
зависшего "Загружаем…" или падения страницы при сетевой ошибке. Битые
изображения/видео (`onerror`) больше не оставляют сломанную иконку.

**Валидация загрузок в админке.** Раньше можно было загрузить файл любого типа
и любого размера. Теперь: картинки — только `image/*`, до 15 МБ; видео —
только `video/*`, до 200 МБ; ошибка показывается до отправки в Storage.

**Дублирование кода.** Лайтбокс (открытие фото/видео на весь экран) был
дословно продублирован в `event.js` и `album.js` → вынесен в общий
`lightbox.js`. Теперь баг фиксится в одном месте.

**SEO.** `index.html` — canonical, Open Graph, Twitter Card, JSON-LD
Organization. `event.html`/`album.html` — то же самое плюс JS донабрасывает
точные title/description/og:image/JSON-LD Event после загрузки данных.
**Важно:** это работает для браузеров и части краулеров (Google это умеет), но
НЕ работает для парсеров, не выполняющих JS (некоторые старые боты соцсетей) —
для них будет виден только дефолтный OG сайта, а не конкретного события. Это
ограничение статического сайта без серверного рендеринга; полноценный fix —
Netlify prerendering/SSR-функция под каждое событие, это отдельная задача.

**robots.txt / sitemap.xml / 404 / privacy / terms** — добавлены. Sitemap на
Netlify отдаётся динамически (`netlify/functions/sitemap.js`) и реально
подтягивает опубликованные события/альбомы из Supabase; на других хостингах
будет использован статический fallback `sitemap.xml` (только главная).
**privacy.html и terms.html — это черновики-заготовки**, не юридический текст:
нужно заполнить реальными формулировками (в идеале — с юристом), там оставлены
явные пометки-подсказки.

**netlify.toml** — заголовки безопасности (X-Content-Type-Options,
X-Frame-Options, Referrer-Policy), `noindex` на `/admin/*`, разумное кэширование
(HTML без агрессивного кэша — правки контента видны сразу; JS/CSS — умеренно,
т.к. без хэшей в именах файлов агрессивный кэш означал бы, что пользователи не
увидят обновлений).

**Аналитика** — `analytics.js`: по умолчанию ничего никуда не отправляет
(privacy-first). Включается через `ANALYTICS` в `config.js` (Plausible или
GA4). Уже расставлены события: `event_view`, `ticket_click`, `album_view`,
`outbound_click`.

**Дашборд админки** — добавлены счётчики «Альбомы», «Категории билетов» и блок
«Ближайшее событие».

**Фавикон/иконки** — `favicon.svg` + `apple-touch-icon.png`/`favicon.ico` в
стиле бренда (тёмный круг, сиреневое кольцо, «МЛ»), т.к. в архиве не было
готовых иконок.

## v2 — правки после первого деплоя

- **Бренд-круг в hero теперь настоящий 3D-шар**: объёмная светотень (не плоское

  ничего не переворачивается и не исчезает. Зелёное (мятное) декоративное
  кольцо вокруг убрано полностью, как и просили.
- **Описание события убрано с карточки на главной** — теперь оно показывается
  только на странице самого события (`event.html`), не в стопке афиш на
  главной.
- **Раздельный фон для тёмной и светлой темы.** Админка → «Контент сайта» —
  теперь два независимых блока: «Фон сайта — Тёмная» и «Фон сайта — Светлая»,
  каждый со своим цветом/картинкой/затемнением. Сайт сам подхватывает нужный
  фон в момент переключения темы (кнопка Dark/Light в шапке).
  → миграция `migration_theme_backgrounds.sql` (добавляет колонки,
  переносит старые значения в «тёмную» тему, ничего не ломает).
- **Отметка «Вход бесплатный» у событий.** В форме события — чекбокс
  «Вход свободный (бесплатно)». Если включён: на карточке и странице события
  вместо цены/статуса билетов показывается плашка «Вход свободный», кнопка
  покупки билета скрывается.
  → миграция `migration_free_entry.sql` (добавляет колонку `is_free`).
- **Карта Google на странице события** (уже было добавлено в v1) — без
  API-ключа, по полю «место проведения» + «город».
- **Админка полностью переоформлена в стиле сайта**: тот же шрифт (Unbounded
  для заголовков), та же палитра акцентов (коралл/фиолетовый/мятный),
  скруглённые карточки и pill-кнопки вместо прямых углов, акцентная подсветка
  активного пункта меню, значок «Бесплатно» в списке событий, брендированный
  шар на экране входа.

### Что нужно сделать в Supabase (по порядку, если ещё не делал)
1. `migration_all.sql` — если сайт уже работает с событиями, скорее всего уже применена.
2. `migration_security_fix.sql` — обязательно, закрывает реальную дыру безопасности.
3. `migration_theme_backgrounds.sql` — новое, для раздельного фона тем.
4. `migration_free_entry.sql` — новое, для отметки «Вход бесплатный».

Каждый файл — целиком скопировать в Supabase → SQL Editor → New query → Run.
Порядок 1→2→3→4, каждый можно запускать повторно без вреда.

## v9 — адаптив + собственная аналитика (по ТЗ)

### Мобильная адаптивность (сделано)
- Реальные источники горизонтального overflow (не просто `overflow-x:hidden`
  как затычка): стопка афиш на главной не была обрезана контейнером — боковые
  карточки в стеке буквально вылезали за пределы экрана на мобильном
  (`.events-stack{overflow:hidden}`); слишком крупный минимум у заголовка
  hero (`clamp(80px,...)` → `clamp(46px,...)`); фиксированная ширина поля
  поиска в админке (300px → `width:100%;max-width:300px`).
- Полноценное мобильное меню вместо `nav{display:none}` — гамбургер с
  анимацией, открывающаяся панель, закрытие по клику вне/по ссылке/по Esc
  (`nav.js`), touch-таргеты ≥44px.
- Админ-панель на мобильном — сайдбар превращается в нижнюю панель навигации
  (как в приложениях), а не просто сжимается; кнопки «Открыть сайт»/«Выйти»
  переехали в компактный блок в углу.
- Ряд билета (`ticket-row`) на мобильном — вертикальная раскладка
  (название / цена+статус / кнопка на всю ширину), кнопка никогда не
  сжимается до нечитаемого состояния.
- Лайтбокс — `dvh` вместо `vh` на мобильном (корректно с адресной строкой
  Safari), safe-area отступы для кнопки закрытия и стрелок.
- Карточки афиш — уменьшены под мобильные брейкпоинты (180→160→148px) с
  пересчётом контейнера, чтобы не обрезались собственным overflow:hidden.
- Защита от длинных строк (overflow-wrap) — заголовки, email/соцсети,
  общий safety-net `html,body{max-width:100%;overflow-x:hidden}` (уже ПОСЛЕ
  устранения реальных причин, как просили в ТЗ, а не вместо них).

### Собственная аналитика (сделано)
- Таблицы `analytics_sessions` / `analytics_events` в Supabase, RLS: аноним
  может только писать свои события, читать агрегаты может только админ
  (`migration_analytics.sql`).
- `analytics.js` расширен (не заменён): session_id в localStorage (сессия
  живёт 30 мин без активности), heartbeat каждые 20 сек через Page
  Visibility API — активное время не считается, пока вкладка в фоне;
  единый `window.manili_track(name, params)`; единая декларативная система
  `data-track="..."` для новых кликов (клик по афише, скачать, поделиться,
  соцсети, hero-кнопка) — старые явные вызовы (`ticket_click`, `event_view`,
  `album_view`) не трогал, работают как раньше, дублирования нет.
- Новый раздел «Аналитика» в админке: посещения, просмотры, среднее
  активное время, все клики, клики «Купить», клики по афишам, просмотры
  альбомов; график сессий по дням (свой лёгкий SVG-бар-чарт, без тяжёлых
  библиотек — под референс, но в бренд-палитре: мятный/коралл); разбивка по
  устройствам; таблица по афишам (просмотры/клики/переходы/CTR); топ кнопок.
  Фильтры периода: сегодня/7/30/90 дней/всё время. Все цифры — из реальных
  Supabase-запросов, ничего не захардкожено.
- На дашборде — краткая сводка аналитики за 7 дней + ссылка на полный раздел
  (по ТЗ п.27).

### Честные ограничения (важно)
- Полная защита аналитики от накрутки/спама (rate-limit по IP, капча) требует
  серверной прослойки (Netlify Function) — в ТЗ это тоже обозначено как
  опциональный следующий шаг, а не обязательный для MVP. Сейчас запись идёт
  напрямую в Supabase с клиента, под RLS и белым списком имён событий.
- Клиентская агрегация в разделе «Аналитика» тянет сырые события за период и
  считает суммы в браузере — для нынешнего объёма трафика это нормально;
  при очень большом трафике стоит перейти на серверную агрегацию
  (SQL-функция/представление).
- Событие может не долететь до Supabase, если пользователь мгновенно уходит
  со страницы (переход по ссылке отменяет ещё не отправленный запрос) — это
  общее ограничение трекинга без `sendBeacon`-совместимого API у Supabase;
  на практике теряется небольшой процент кликов-переходов, не искажающий
  общую картину.
- Нужно выполнить `migration_analytics.sql` в Supabase, иначе раздел
  «Аналитика» покажет ошибку с подсказкой это сделать.

## v10 — доводка аналитики и адаптива по чек-листу ТЗ

- **Исправлена критичная нестыковка данных аналитики:** события

  референса не использовалась.
- **Физику проверял численно** (в песочнице нет браузера/GPU): прогон
  симуляции в Node выявил, что флаг кумулятивно «уплывал» вниз (габарит 3.6
  вместо 1.5). Добавил возвращающую силу к исходной форме (shape-matching) +
  ограничение растяжения рёбер — после этого 2000 шагов на десктопной и
  мобильной сетке стабильны, флаг колышется на месте и не разваливается.
- Под флагом: отсчёт до события, кнопка «Информация» (на страницу события)
  и кнопка «Поделиться» (нативный share на телефоне, копирование ссылки на
  десктопе) — обе с аналитикой.
- Блок компактный (не растянут на весь экран, как прежнее промо), качество
  афиши сохраняется за счёт high-DPI-текстуры и anisotropy.
- **Оптимизация под мобильные** (анимация включена на всех устройствах по
  твоему решению): мельче сетка симуляции на телефонах, ограничен
  pixelRatio, симуляция идёт только пока блок виден (IntersectionObserver)
  и вкладка активна (Page Visibility) — не греет батарею в фоне.
- Фолбэк: если афиша не загрузилась, three.js не подтянулся, WebGL недоступен
  или включён prefers-reduced-motion — показывается статичная афиша, без
  ошибок и пустых мест.

### Ограничение
- Реальный визуальный результат (как именно колышется ткань, читаемость
  афиши, плавность на конкретном телефоне) можно оценить только в браузере —
  в песочнице нет WebGL. Физика проверена математически, но финальную
  визуальную приёмку нужно сделать на живом сайте после деплоя. Если ткань
  будет колыхаться слишком сильно/слабо — это один параметр (`amp`/`GRAV`
  в flag.js), быстро подстрою по твоему фидбеку.

## v12 — возврат промо-видео (флаг убран)

- Флаг-ткань убрана по решению заказчика (выглядела недостаточно объёмно).
  `flag.js` удалён, three.js больше не грузится.
- Возвращён прежний промо-блок ближайшего события: видео (или постер, если
  видео нет) на всю ширину блока с градиентным затемнением, поверх —
  eyebrow, название, дата/место, отсчёт и кнопки. Из полезного от прошлой
  итерации оставлены кнопки «Информация» + «Поделиться» (нативный share на
  телефоне / копирование ссылки) и аналитика на них.
- Качество видео: на публичной странице `preload="auto"` (браузер грузит
  видео целиком, а не только метаданные); в админке добавлена подсказка
  загружать исходник в 1080p+ MP4/H.264 — потеря качества чаще всего именно
  из-за пережатого исходника, а не из-за отображения.

## v13 — промо-блок на главной: диагностика и полировка

- Кнопки «Информация»/«Поделиться» **уже были** овальными (border-radius:999px)
  с рамкой и реакцией на hover (инверсия цвета + лёгкий подъём) — это готовый
  `.btn` класс, ничего не пришлось добавлять заново.
- Убрал лёгкое обесцвечивание (`filter:grayscale(.1)`) с промо-видео/фото —
  теперь цвет полностью «живой», без даже небольшой приглушённости.
- **Важная находка про «полотно»:** блок ближайшего события на главной
  показывается ТОЛЬКО если у события загружено промо-видео (запрос строго
  фильтрует `promo_video_url IS NOT NULL`). Если то, что видно на скриншоте —
  статичная картинка без движения, это почти наверняка кадр-превью
  (`poster`) видео-тега, который виден, пока сам видеофайл ещё не
  прогрузился и не начал играть — НЕ баг вёрстки. autoplay/muted/loop/preload
  уже настроены правильно, "растягивания" с искажением пропорций в CSS
  нигде нет (везде `object-fit:cover`, только обрезка, никогда не деформация).
  Раз сайт медленно грузится из РФ через Netlify (обсуждали ранее) — скорее
  всего именно поэтому видео долго остаётся на кадре-превью. Если после
  деплоя этой версии видео всё равно не проигрывается — пришли ссылку на сам
  видеофайл через админку (или его вес/длительность), проверю отдельно.
